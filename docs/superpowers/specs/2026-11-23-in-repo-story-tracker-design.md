# In-repo story tracker

Дата: 2026-11-23  
Статус: approved

## Проблема

Без внешнего трекера цикл «idea → ветка → PR» есть, а бэклога и наглядной истории задач нет. Подключать GitHub Projects / токены / `gh` ради прототипа — лишнее трение. Внешний трекер через MCP полезен, когда он уже есть, но не должен быть обязательным.

## Цель

Встроенный примитивный трекер в репозитории:

- ноль настройки (без токенов, `gh`, создания Project);
- человек или агент кладут задачу в бэклог;
- агент ведёт статусы в том же месте, что и user story;
- read-only борд открывается в браузере без `npm run`;
- внешний MCP-трекер опционален: при наличии задача зеркалится локально.

## Источник правды

Каталог `docs/stories/`. Один файл — одна задача. Имя: `<id>-<slug>.md`.

Frontmatter:

```yaml
---
id: "001"
title: "Краткий заголовок"
status: backlog   # backlog | in_progress | done
branch: ""
pr: ""
external: ""      # ссылка/id во внешнем трекере, если есть
---
```

Тело файла — по `docs/user-story-template.md`. Пишут только человек или агент. Браузерный борд ничего не меняет.

## Цикл агента

1. Идея в чате без файла → создать story (`backlog` или сразу `in_progress`).
2. «Положи в бэклог» → только файл, без ветки и кода.
3. «Сделай / возьми» → `in_progress`, ветка `feat/<id>-short-name`, тесты → реализация → PR со ссылкой на story.
4. Готово → `done`, заполнить `branch` / `pr` при наличии.
5. Внешний MCP: зеркало в `docs/stories/` + `external`; нет трекера — шаг пропустить без ошибок.
6. После создания или смены статуса — обновить `docs/stories/board-data.js` (скрипт `regen-board.mjs` или руками агентом).

Одна активная story на ветку и PR.

## Борд

`docs/stories/board.html` + снимок `board-data.js`.

Браузер по `file://` не читает соседние `.md`, поэтому данные — сгенерированный JS. Три колонки: backlog / in progress / done. Карточка показывает id, title, превью; клик раскрывает детали. Без drag-and-drop и без Next.js.

Открытие: двойной клик или `open docs/stories/board.html`.

## Discoverability

- `docs/stories/README.md` — контракт папки и как открыть борд;
- корневой `README.md` — упоминание встроенного бэклога;
- `AGENTS.md` / `CLAUDE.md` — порядок работы со stories;
- PR template — ссылка на `docs/stories/…`.

## Вне scope v1

- Запись статусов из браузера;
- UI GitHub Projects;
- полноценный двусторонний MCP-адаптер;
- борд внутри Next.js-приложения.

## Тестирование приёмки

1. В `docs/stories/` лежит хотя бы одна story с валидным frontmatter.
2. `node docs/stories/regen-board.mjs` пересобирает `board-data.js` из `*.md`.
3. `board.html` открывается без сервера и показывает карточки по статусам.
4. Правила в `AGENTS.md` описывают цикл без требования внешнего трекера.
