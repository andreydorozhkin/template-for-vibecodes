# User story

**Как** человек, работающий с агентом, **я хочу** получать проверяемые результаты и только необходимые уточнения, **чтобы** делегировать задачи без лишних согласований.

## Критерии приёмки

1. Дано задача с обратимыми техническими деталями. Когда агент выбирает реализацию. Тогда он использует контекст и соглашения проекта, не требует согласования каждого шага.
2. Дано неоднозначность, влияющая на продуктовый результат, объём или существенный риск. Когда контекст не даёт ответа. Тогда агент задаёт короткий вопрос с рекомендацией, а независимую работу продолжает.
3. Дано изменение поведения. Когда агент планирует проверки. Тогда связывает их с критериями приёмки, выбирает глубину по риску и явно отмечает непроведённые проверки.
4. Дано небольшая правка документации. Когда агент выполняет задачу. Тогда достаточно проверки содержания и diff; новые автотесты и отдельный план не обязательны.
5. Дано завершённая задача. Когда агент передаёт результат. Тогда кратко сообщает изменения, фактическую проверку и существенные ограничения.
6. Дано вопрос, обсуждение или ревью без поручения работы. Когда агент отвечает. Тогда story не создаётся; уточнения порученной задачи дополняют существующую story.
7. Дано gitleaks недоступен или проверил 0 коммитов. Когда агент готовится к пушу. Тогда пуш не выполняется; CI не заменяет локальную проверку.
8. Дано справочные подробности gitleaks, SonarQube и деплоя. Когда агент читает `AGENTS.md`. Тогда видит обязательные правила и ссылки на документацию с подробностями.
9. Дано существующее окружение с нужными данными или неизвестным состоянием. Когда агент готовится к переинициализации. Тогда до смены ключей и удаления томов согласует сохранение данных; автоматическое удаление пользовательских данных запрещено.

## Не входит в задачу

- Изменение стека, автоматизация деплоя и создание PR.
- Новая система трекинга или обязательный дополнительный документ на каждую задачу.

## Проверка

- Ручная сверка инструкций с пятью сценариями выше: пройдена. Обычные решения, существенная неоднозначность, выбор проверок, правка текста и итоговый отчёт явно описаны в `AGENTS.md`.
- После ревью проверены также критерии 6–9: уточнены границы создания story, обязательность gitleaks до пуша и защита существующих данных. Справка gitleaks перенесена в `docs/security-checks.md`, для SonarQube и деплоя оставлена ссылка на `docs/production.md`; файлы и якоря ссылок проверены.
- `npm run stories:board`: борд пересобран с задачей 006.
- `git diff --check`: без ошибок.
- Перед пушем прошли `npm run lint`, `npm run typecheck`, `npm test` (7 тестов), `npm run test:functions` (4 теста) и `npm run test:stories` (2 теста).
- Gitleaks по истории git с подключённым общим `.git` worktree: утечек не найдено, проверено ненулевое число коммитов.
