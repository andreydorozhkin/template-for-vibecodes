# User story

**Как** человек или агент с параллельными ветками, **я хочу** чтобы встроенный трекер `docs/stories/` не ломал rebase/merge из‑за пересечения номеров и снимка `board-data.js`, **чтобы** готовые задачи с `main` не конфликтовали с новой story на feature-ветке.

## Контекст

На rebase `feat-gitleaks-docs-skill` на `origin/main` после мержа stories `002` и `003` снова всплыл конфликт: две ветки взяли один и тот же числовой id, плюс `board-data.js` постоянно конфликтует как сгенерированный снимок.

## Критерии приёмки

1. Дано две параллельные ветки, каждая добавляет новую story. Когда обе мержат в `main`. Тогда id не пересекаются без ручного переименования (правило выделения id или проверка в CI).
2. Дано конфликт только в `board-data.js` при rebase/merge. Когда следуют процессу репозитория. Тогда конфликт либо не возникает (снимок не в git / генерится в CI), либо снимается одной командой без ручного склеивания JSON.
3. Дано агент создаёт story. Когда смотрит README/`AGENTS.md`. Тогда явно сказано, как выбрать следующий id (в т.ч. с учётом `origin/main`, не только локального каталога).
4. Дано PR с новой story. Когда CI. Тогда падает при дубликате id или двух файлов с одним префиксом номера.

## Не входит в задачу

- Внешний трекер (GitHub Projects / MCP) как замена `docs/stories/`.
- Переписывание истории уже смерженных stories `001`–`004`.
